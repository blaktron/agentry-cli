# RUNNER-DEVIATIONS — divergences from RUNNER-PLAN.md and its research annex

RUNNER-PLAN.md is immutable. When implementation reality disagrees with it (or with the
research annex `agentry-framework-research.md`), the divergence is recorded here with its
reason — never silently patched into the plan. Same register discipline as the core repo's
`DEVIATIONS.md`.

| id | date | what diverged | why | status |
|---|---|---|---|---|
| DR-1 | 2026-08-30 | `exec: {commands}` is enforced by argv0 allowlist + shim `PATH` inside the shared tools container, not by a per-run image containing only the declared binaries (annex §6 ideal: "hard (binary absence)"). | One locally built runner image keeps first-use install to a single `docker build`; a per-run minimal exec image is real work (base-image resolution per command) deferred to the backlog. The receipt's `capabilities_enforced.exec` string names the actual mechanism so the posture stays honest. | open (backlog: dedicated exec server image) |
| DR-2 | 2026-08-30 | Runner/tool/proxy image build context lives in this repo (`runnerimage/`, embedded into the CLI binary), not under `deploy/runner/` in the core repo as annex §8 sited it. | RQ1 self-containment: the tools server source must ship inside the CLI so first use needs no access to our repos or registries; the context embeds stdlib-only sources and builds locally. | accepted |
| DR-3 | 2026-08-30 | Gateway runs containerized only in v1; the `docker mcp` CLI-plugin mode (binary install into `~/.docker/cli-plugins/`) is documented for manual setups but never auto-installed. | Auto-downloading a host binary from GitHub at run time is supply-chain surface the containerized path avoids; the container is pinned by policy and pulled through the docker trust path. | accepted |
| DR-4 | 2026-08-30 | Budgets: `--timeout` and `--max-turns` are hard-enforced (deadline kill; NDJSON tool/turn event counting); `--max-cost` is recorded from harness usage events but not yet a hard stop. | docker-agent exposes cost only in its event stream; killing on a parsed running total is easy to get wrong across adapters. Recorded, not enforced — envelope says so. | open (M-R4) |
| DR-5 | 2026-08-30 | `kind: mcp-server` packages are not yet attachable as gateway backends for other agents' runs (annex R10); `dependencies.agents` stays informational, matching registry v1. | Needs dependency resolution + per-dep verification + catalog synthesis; scoped to M-R5 so v1 ships the agent path end to end first. | open (M-R5) |
| DR-6 | 2026-08-30 | The LLM egress proxy allowlists CONNECT targets by host:port; it does not inspect TLS. A harness that ignored `HTTPS_PROXY` would fail closed (internal network has no route), not fail open. | Fail-closed is the acceptable direction; per-adapter empirical proxy verification is M-R4 work. | open (M-R4) |
| DR-7 | 2026-08-30 | This machine (framework author) has no docker engine, so M-R2/M-R3 acceptance scripts gate on `docker info` and the execute path ships with fake-docker unit coverage instead of a local E2E proof. | Environment fact. Scripts are written to run unchanged on any docker CE host; first real E2E run is an operator step. | open (needs a docker host) |
| DR-8 | 2026-08-30 | `output.schema.json` (§R2) is enforced as *the schema rides in the prompt + the final message must parse as JSON* (exit 17 otherwise); the runner does not yet run full JSON-Schema validation, nor emit docker-agent's harness-native `structured_output` block. | Go has no stdlib JSON-Schema validator and the framework takes no third-party deps in v1; docker-agent's `structured_output` YAML shape was not verified by the survey, and guessing it would fail runs at the harness. Validate-with-retry lands with the M-R4 adapter conformance work. | open (M-R4) |
| DR-9 | 2026-08-30 | Branding: the runnable packages are branded **BriefAgents** in user-facing surfaces (CLI help and prompts, README, docs/site, the tools-server catalog title, the runner-contract postscript, the template repo `blaktron/agentry-template`). RUNNER-PLAN.md still says "agent" — it is immutable, and its uses are the technical noun. | Operator decision 2026-08-30. Machine-readable identifiers deliberately do NOT change: manifest kinds, JSON/envelope keys (`agentry: run/v1`, `agentContainer`), container/network names (`agentry-<runid>-agent`), the `agentry-tools` catalog name, and the MCP serverInfo name `agentry-runner-tools` all stay — receipts, scripts, and installed plans must not break over branding. | accepted |
